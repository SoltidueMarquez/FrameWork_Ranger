# ADR-EC-005：生产程序集显式接入与分层架构导航

- **状态**：部分被取代；生产程序集接入继续有效，导航方式由 [ADR-EC-006](./ADR-EC-006_Expandable_Compound_Architecture_Graph.md) 取代
- **日期**：2026-08-19

## 背景

原架构目录只认识 Core Runtime 与 Core Editor。Resource Management 采用独立模块与适配程序集后，类型不会被扫描，源码索引也无法越过旧目录边界。继续向硬编码白名单追加程序集虽然能暂时显示资源模块，但每个新模块都会再次修改核心编辑器，并且单张扁平类图会随类型数量持续恶化。

## 决策

1. 用程序集级 `FrameworkArchitectureAssemblyAttribute` 作为生产程序集的显式接入边界。
2. Attribute 同时声明稳定分组路径、中文显示路径、程序集职责和排序；目录构建器据此自动构建父子分组。
3. 显式接入程序集中的顶层类、接口、结构体和枚举必须维护类型级 `FrameworkArchitectureAttribute`，缺失即产生目录诊断并由 EditMode 测试阻止回归。
4. Tests、Samples 与第三方程序集默认不接入；需要展示时必须另行决策，不能因为目录位于 Framework_WWJ 下而自动混入。
5. 架构页先显示直接子分组和聚合依赖，打开叶分组后才显示原有逻辑层类型图。该导航方式已由 ADR-EC-006 的单画布可展开容器取代。
6. 源码索引搜索整个 Framework_WWJ 根目录，并为同文件辅助类型提供声明名回退定位。

## 原因

- 显式接入使模块拥有自己的架构目录注册信息，避免中心程序集反向依赖所有模块。
- 稳定路径可以容纳未来的 Pooling、Event 等模块以及各自适配器，而无需增加新的固定枚举筛选项。
- 分层视图把“模块之间的关系”和“模块内部的类型关系”分开，降低跨模块连线噪音。
- 结构体和枚举也是资源模块的重要契约；只展示类和接口会遗漏 `ResourceKey`、后端类型与诊断值对象。

## 被否决方案

### 继续追加程序集名称白名单

每增加一个模块都需要修改 Core Editor，模块无法自描述，且无法自然生成层次。

### 按磁盘目录自动扫描所有程序集

会把 Samples、Tests、生成代码和未来工具程序集混入生产视图，发现边界不稳定。

### 在单张图中为所有类型加折叠框

Phase 1.4 曾认为它会保留过高的布局和连线复杂度。实际使用证明钻入式导航损失了脚本与关系的整体可见性，因此该否决在 Phase 1.5 被 ADR-EC-006 取代，并通过确定性泳道、关系聚合和筛选控制复杂度。

## 结果

- 新生产模块必须在其 `AssemblyInfo.cs` 声明分组元数据，并为顶层核心类型维护职责 Attribute。
- 架构目录和源码索引成为跨模块的通用基础设施。
- 当前逻辑层图继续存在，但作用域缩小为一个叶分组。
- 新模块交付测试应把“架构目录可见、职责完整、源码可定位”纳入标准验收。
