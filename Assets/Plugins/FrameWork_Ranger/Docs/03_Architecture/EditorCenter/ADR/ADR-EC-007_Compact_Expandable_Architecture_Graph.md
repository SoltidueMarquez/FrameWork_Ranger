# ADR-EC-007：紧凑可展开架构节点图

> 状态：Accepted  
> 日期：2026-08-22  
> 取代范围：ADR-EC-006 的全局七列泳道布局，以及早期“不允许拖动”约束

## 背景

ADR-EC-006 确认单画布、分组原地展开和折叠代理，但把每个分组绘制成横跨七个全局逻辑层的纵向泳道。折叠状态仍占用宽大区域，多个大分组不容易作为高层架构节点阅读；嵌套展开后也会携带大量不属于当前分组的空列。完全禁止拖动则使临时整理密集关系缺少手段。

HTY 的状态机编辑器证明“高层节点 + 原地查看内部状态”适合层次结构阅读；YokiFrame 展示了圆角卡片、主题层级和曲线箭头的可读性。参考价值在交互和视觉原则，不在复制其钻入导航或 Avalonia 实现。

## 决策

1. 继续使用一张 IMGUI Compound Graph 和既有共享视口，不迁移 UI Toolkit/GraphView。
2. 折叠分组是固定紧凑大卡片；根级和同级分组稳定横排并确定性换行。
3. 分组原地展开为复合容器，只包围直接子组和直属类型；子组仍以同一种大节点语义递归展开。
4. 每个分组只为直属类型实际使用的逻辑层建立局部列，不再共享全局七列坐标。
5. 隐藏关系映射到最近折叠祖先，并按可见端点和关系种类聚合。
6. 所有可见卡片允许会话内拖动；展开标题移动完整子树。嵌套偏移限制为父内容区左上边界以内，右、下偏移允许父容器扩展。
7. 位置只以稳定键写入 `SessionState`；折叠保留偏移，重启 Unity 恢复自动布局。
8. 搜索临时展开期间禁止拖动和改变展开集合，避免临时节点污染用户布局。
9. 布局以目录、展开、位置、搜索和关系筛选 revision 缓存；绘制阶段只消费缓存并按视口裁剪。
10. 节点和关系采用深浅主题圆角卡片、端口、贝塞尔曲线、箭头、Hover/Selected 与一跳弱化；低缩放逐级隐藏次要文字。

## 后果

### 正向

- 折叠视图直接表达大分组之间的关系，画布密度显著降低。
- 局部分层消除无用空列，展开容器与目录所有权保持一致。
- 临时拖动改善关系密集区域的阅读，又不产生项目资产和版本冲突。
- revision 缓存使普通 IMGUI Repaint 不承担目录、布局和关系聚合开销。

### 代价

- 同一逻辑层不再跨全部分组严格垂直对齐；跨分组比较依赖层标签和颜色。
- SessionState 坐标不跨 Unity 会话、设备或团队共享，这是有意边界。
- 手工偏移可能形成局部视觉重叠；工具栏重置布局是恢复确定性自动布局的统一出口。
- IMGUI 的视觉和输入细节仍需在深浅主题及多个缩放等级进行真实窗口检查。

## 保留决定

ADR-EC-006 关于单画布、目录驱动、搜索临时展开、折叠代理、详情和共享视口的决定继续有效。Runtime API、模块生命周期、架构元数据、程序集接入和序列化格式均不受本 ADR 影响。
