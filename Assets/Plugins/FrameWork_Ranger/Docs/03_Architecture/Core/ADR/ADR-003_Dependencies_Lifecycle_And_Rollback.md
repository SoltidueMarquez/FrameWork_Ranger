# ADR-003：精确类型依赖、串行生命周期与失败回滚

- 状态：已接受
- 日期：2026-08-07
- 所属阶段：第一阶段——模块模型与驱动骨架

## 背景与约束

仅靠优先级无法表达“模块 B 必须在模块 A 成功后加载”，并且并行初始化会放大取消、部分成功和回滚语义。第一阶段优先追求可解释、可测试的确定性。

## 候选方案

1. 只按配置顺序或优先级加载。
2. 接口/基类依赖与运行时实现选择。
3. 具体 Module 类型依赖、稳定拓扑排序、严格串行生命周期。

## 决定

采用方案 3。模块在代码中声明具体 `ModuleBase` 类型。`ModuleGraphResolver` 使用 Kahn 拓扑排序；依赖先于优先级，同一就绪层按较小 `LoadPriority`、配置序号和类型全名排序。

加载使用 UniTask 严格串行。Load 可由 Entry 销毁或 Shutdown 取消；Unload 不接受取消。Scope 加载失败时按实际成功加载顺序的逆序回滚，卸载单点异常被聚合但不阻断其余清理。

## 影响与明确非目标

- Global 不能依赖 Scene；Scene 可以依赖 Global 或同 Scene。
- 自依赖、缺失/禁用依赖、重复类型与循环依赖在任何克隆前失败。
- 已进入 Load 但尚未成功的模块负责清理自己的临时资源；骨架只回滚已成功 Loaded 的模块。
- 第一阶段不做并行加载、可选依赖、接口绑定和运行时依赖替换。

## 验证方式

- EditMode 排序、方向、缺失、重复、自依赖与循环诊断测试。
- PlayMode Global→Scene 时序、Scene/Global 失败、逆序回滚与 Shutdown 测试。
