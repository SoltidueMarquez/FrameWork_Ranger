# Framework_WWJ 骨架决策问题

> 状态：第一阶段决策问题归档。问题已经通过用户确认的实现计划与 [Core ADR](./ADR/README.md)关闭；未来需求变化时新增 ADR，不改写本问题原文。

## 1. SO 模板与运行时实例

1. 模块 SO 是同时保存配置与逻辑，还是只保存配置并创建独立 Handler？
2. 所有模块是否必须克隆，还是无运行状态的纯配置模块可以共享？
3. 克隆使用 `Object.Instantiate` 还是由模块工厂负责？
4. 运行时克隆是否需要隐藏、统一命名或设置 `HideFlags`？
5. 原始资产、克隆模块和 Handler 分别由谁持有与销毁？
6. Domain Reload 关闭时，如何保证上次 Play Mode 状态不会残留？

## 2. 模块身份与访问

1. 模块唯一性按配置 key、具体类型、接口类型还是资产 GUID 判断？
2. 是否允许同类型多实例模块？如果允许，调用者如何区分？
3. 业务代码通过注入的上下文、Runtime 查询、泛型 API 还是受控静态门面访问模块？
4. 重复模块是报错、警告并跳过，还是允许场景模块覆盖全局模块？

## 3. 生命周期

1. 第一版最少需要哪些阶段：创建、加载、启用、暂停、卸载、销毁？
2. 加载是否必须支持异步？若支持，使用 Coroutine、UniTask、Task 还是自定义句柄？
3. 异步加载是否需要取消、超时和进度？取消由谁发起？
4. 某个模块加载失败后，是终止全部、回滚已加载模块，还是跳过失败模块继续？
5. 卸载方法抛出异常时，是否继续清理其余模块？
6. 模块能否被重复加载或卸载，还是错误使用直接记录失败？

## 4. 排序与依赖

1. 模块拥有两个独立优先级，还是加载优先级加默认反序卸载？
2. 数值越小越早，还是数值越大越早？
3. 相同优先级如何保持稳定顺序？
4. 优先级是否足以表达依赖，还是需要 `DependsOn`？
5. 缺失依赖和循环依赖应在编辑器、启动时还是两处都验证？

## 5. Global 与 Scene 作用域

1. 全局 Runtime 由首个场景 Entry 创建，还是由 `RuntimeInitializeOnLoadMethod` 自动创建？
2. 全局配置是项目唯一资产，还是允许不同启动配置？
3. 场景模块由场景中的 Entry 显式引用配置，还是按场景名查找配置？
4. additive 多场景同时加载时，是每场景一个作用域还是共享一个 Scene Runtime？
5. 场景卸载和应用退出时的顺序是什么？
6. 全局与场景模块同 key/类型时，覆盖、并存还是错误？
7. 场景切换期间，全局模块是否接收切换前后通知？

## 6. Module + Handler

1. Handler 是接口、抽象基类还是 Odin 可序列化的多态对象？
2. Module 与 Handler 是一对一，还是一个 Module 可选择不同 Handler 实现？
3. Handler 是否允许持有 UnityEngine.Object 引用？
4. 生命周期由 Module 覆写、Handler 覆写，还是 Module 固定转发给 Handler？
5. 简单模块能否不使用 Handler，避免空转发层？
6. 框架 Runtime 自身若采用 Handler，如何避免“框架必须先运行才能加载框架模块”的自举循环？

## 7. Tick 与运行控制

1. Update、FixedUpdate、LateUpdate 是否分别使用显式能力接口？
2. 模块默认自动运行，还是加载完成后由 Runtime 统一启用？
3. 是否需要全局 Pause/Resume、模块级 Pause/Resume 或两者都不需要？
4. Tick 中添加/移除模块是否允许？若不允许，如何延迟变更？

## 8. 配置与 Odin 编辑体验

1. 全局配置、场景配置和模块资产的创建菜单与目录约定是什么？
2. 配置列表直接引用 Module SO，还是使用带开关、key、排序覆盖的 Entry？
3. 优先级来自模块资产还是配置 Entry？同一模块在不同作用域需要不同顺序吗？
4. Odin Inspector 需要哪些即时校验、重复提示和只读运行状态？
5. 第一版是否依赖 Odin 序列化接口/抽象类，还是只用 Odin 改善 Inspector？

## 9. 诊断、测试与示例

1. Runtime 最少暴露哪些只读状态用于调试？
2. 日志使用 `Debug`、可替换日志接口还是后续日志模块？
3. 需要哪些 EditMode 测试验证排序、克隆、查询和失败回滚？
4. 需要哪些 PlayMode 测试验证跨场景 Global、Scene 卸载和原资产不被污染？
5. 最小示例是纯测试模块，还是立即绑定第一个游戏目标？

## 10. 下一轮建议顺序

先确认“模块实例与 Handler → 生命周期与错误 → 排序依赖 → Global/Scene → 访问与 Tick → Odin 编辑体验 → 测试”。后续选择依赖前序答案，避免一次讨论过多孤立细节。
