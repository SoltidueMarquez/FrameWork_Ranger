# Phase 1.5 单画布可展开代码架构图验收与复盘

> 日期：2026-08-20  
> 状态：代码与自动化验收通过；真实窗口视觉交互待用户人工确认

## 实际交付

- 移除分组页与叶级类型页之间的互斥导航，改为一张 Compound Graph。
- 根分组纵向排列；父组、子组和类型节点在同一画布原地展开。
- 七个逻辑层使用全局 X 列，分组使用递归纵向泳道。
- 新 Unity 会话默认全部收起，当前会话通过 `SessionState` 保存用户展开集合。
- 支持逐组展开/收起、全部展开/全部收起、三类关系筛选和标题锚点保持。
- 折叠组内部类型关系映射到可见分组代理，按端点和关系种类聚合。
- 搜索临时展开命中路径并聚焦结果；清空后恢复用户状态。
- 代码架构图使用 10%–200% 缩放，模块依赖图继续使用 35%–200%。
- 类型详情、中文职责、源码路径、Ping 和 Rider 打开保持不变。

## 与计划的实现说明

- 搜索期间禁用手动展开和批量展开按钮。原因是搜索临时状态会强制展开命中路径，继续允许收起会产生“按钮已点击但分组仍展开”的冲突；清空搜索后立即恢复操作。
- 展开状态只保存 GroupId，不保存 Zoom、Pan、类型选择或搜索文本。
- `FrameworkArchitectureHierarchyDrawer` 已移除，由纯 `FrameworkArchitectureGraphLayout` 与统一 `FrameworkArchitectureGraphDrawer` 取代。
- Phase 1.4 的程序集接入、职责 Attribute 和源码索引保持不变；只有钻入式导航被 ADR-EC-006 取代。

## 人工视觉验收

1. 打开 `Framework_WWJ → Framework Center → 代码架构`。
2. 确认初始画布只有“框架核心”和“基础模块”两个收起泳道。
3. 展开“基础模块 → 资源管理 → Runtime”，确认每次展开都发生在同一画布，没有切换页面。
4. 选择 `ResourceModule`：右侧显示中文职责，Ping 与打开脚本可用。
5. 分别关闭“继承、接口、协作”，确认对应连线独立消失。
6. 搜索 `ResourceModule`：路径临时展开并聚焦；清空后恢复搜索前的展开状态。
7. 点击“全部展开”和共享画布“适配”，确认可下降到约 10% 查看完整轮廓；放大后节点仍可准确点击。
8. 展开某个分组后确认其标题位置不发生跳跃式缩放；关闭重开 Framework Center 后展开状态仍存在。
9. 重新启动 Unity，确认分组恢复为默认全部收起。

## 当前结论

代码、目录、编译和自动化行为已经满足 Phase 1.5 门禁。真实编辑器中的视觉密度、按钮手感和低缩放辨识度仍需要用户按上述步骤确认；若视觉结果不符合预期，应继续调整绘制常量与样式，不修改 Runtime 或架构元数据契约。
