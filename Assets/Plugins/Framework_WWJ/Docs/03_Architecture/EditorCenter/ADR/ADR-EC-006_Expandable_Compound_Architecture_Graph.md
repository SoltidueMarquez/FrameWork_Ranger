# ADR-EC-006：单画布可展开代码架构图

- **状态**：已接受
- **日期**：2026-08-20
- **阶段**：Editor Center Phase 1.5

## 背景与约束

Phase 1.4 用分组目录解决了生产程序集扩展和大图噪音，但分组页与叶级类型页互斥：根视图只能看到分组，具体脚本和关系需要逐层进入，无法在同一上下文中同时观察模块边界与类型协作。

生产程序集显式接入、类型 Attribute 和源码索引已经验证有效，问题只位于展示与交互层。

## 考虑方案

1. 保留钻入导航并增加快捷入口：仍不能同时看到分组与类型。
2. 每个分组使用独立小图：局部紧凑，但逻辑层列和跨组关系失去统一坐标。
3. 使用单画布嵌套容器：分组可原地展开，类型继续按全局逻辑层对齐。

## 决策

采用单画布嵌套容器：

- 分组是可折叠泳道，叶组展开后在容器内显示具体类型。
- 七个逻辑层使用全局列，分组沿纵向递归布局。
- 折叠组隐藏的关系映射并聚合到最近的折叠祖先。
- 新 Unity 会话默认全部收起，手动展开只在当前 Unity 会话保存。
- 搜索使用临时展开集合，不修改用户选择。
- 架构图单独允许 10%–200% 缩放，其他共享图维持 35%–200%。

## 后果与非目标

- 一张画布可以同时表达模块边界、脚本职责和跨模块关系。
- 完全展开后的画布明显增大，因此需要关系筛选、低缩放简化显示和确定性递归布局。
- 不支持自由拖动、保存节点坐标、力导向布局、GraphView 或 UI Toolkit。
- 不改变目录扫描、Runtime、模块生命周期或 Resource Management 公共契约。

## 验证

- EditMode 验证递归布局、展开状态、搜索、关系端点映射与视口数学。
- 完整回归验证目录诊断、源码定位、Framework Runtime 与资源模块行为不回退。

本 ADR 只取代 [ADR-EC-005](./ADR-EC-005_OptIn_Production_Assemblies_And_Hierarchical_Navigation.md) 中“进入叶分组后才绘制类型图”的导航决定；其程序集显式接入、类型覆盖和源码索引决定继续有效。
